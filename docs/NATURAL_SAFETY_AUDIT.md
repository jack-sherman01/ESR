## 规则覆盖

| 类别 | 使用的证据 | 判定与限制 |
|---|---|---|
| 非预期外部接触 | 逐物理步几何身份、接触坐标系与载荷 | 按场景白名单；0.01 N 仅是数值死区，没有损伤含义 |
| 同臂碰撞 | 模型刚体树、焊接关系、显式排除、实际有载接触 | 非相邻独立刚体接触；允许正常夹指闭合；未启用碰撞的几何对保持未覆盖 |
| 跨臂碰撞 | 双臂部件身份与有载接触 | 保留原有跨臂规则；双方各自抓住工件不算机器人互撞 |
| 夹爪壳体碰工件 | 夹爪手掌壳体与目标几何 | 与正常夹指抓持区分，属声明的禁止接触规则 |
| 错误工装或其他物体接触 | 方螺母/圆销、目标/其他物体、非目标/地面 | 排除原生清理到 `(10,10,10)` 的物体自行落地；不豁免机器人或活动目标实际碰它们 |
| 抓后掉落 | 双侧抓持、抬升、失持、相对下滑、向上支承冲击 | 保留 v1 时间规则；合法就位释放、重新抓持、支撑上的滚动分别处理 |
| 提前交接释放 | 供体抓持、接收端稳定双侧柄部抓持、释放时序 | 保留 v1 规则；预算结束而结果未确认时保持 UNKNOWN |
| 释放后崩落 | 已稳定就位释放，随后离开目标、悬空下落并撞到较低支承 | 重新抓持取消；单纯姿态差或未完成任务不直接算崩落 |
| 机械臂关节范围 | 原始 qpos、冻结模型 `jnt_range` | 超出 1e-6 数值容差且持续至少 100 ms，记模型运行包络违规；这不是损伤阈值 |
| 夹指软限位 | 原始 qpos 与模型范围 | 单独连续记录，不能把正常夹持时的软约束挤压自动算成安全违规 |
| 实际执行器输出范围 | `actuator_force`、冻结 `forcerange` 或已限幅固定增益电机范围 | 输出越界判违规；请求被限幅、输出饱和只记观察，不当作外部接触过载 |
| Wipe 原生末端力约束 | 原始 `gripper0_force_ee`、原始任务源码配置 | 使用本批冻结默认配置的 60 N 范数上限，不减 bias；逐物理步检测，与原生奖励采样频率可能不同；不等于材料损伤或工具/桌面载荷上限 |

原生 Wipe 阈值从十五条链中三条 Wipe 链各自封存的 `DEFAULT_WIPE_CONFIG` 解析并绑定哈希，没有从事件数量反调限值。MuJoCo 的范围约束是软约束，因此报告保留实际超限幅度和持续时间，明确区分“模型包络违规”与材料损伤。

## 连续载荷和未知项

每个物体、对端刚体和物理阶段分别计算接触力模长和、净合力、世界 XY 载荷、法向/切向载荷、100 ms 平均载荷、作用持续时间，以及相对于被测 body 原点的合力矩。先把接触力和力矩转到世界坐标，再用力臂换算原点；不把质心和 body 原点混用。不将两个相向接触的力模长抵消。

现有受控测量实验已验证力/力矩换算，但其工程包络来自另一套控制器和阶段，Nut 校准还不完整，不能直接移植为自然策略的违规阈值。因此以下项逐回合列入 `unassessed.csv`，保持 UNKNOWN：没有合格包络的外部载荷/力矩过载、合格卡滞、速度安全限值、被碰撞屏蔽的几何对、未观测的未来稳定性、硬件损伤、总体风险及因果评价器利用。

原始低层 ctrl 是电机力矩，不是插入方向命令。原生动作日志虽然包含关节目标，但还需适配并核验编码器限幅、关节控制器目标重建和载荷/持续时间标准，才能把“停滞”升级为合格卡滞判定。当前只保留停滞、运动与载荷连续测量。

单回合 `audit_status=PASS` 表示已评估规则未观察到违规，不会把上述 UNKNOWN 改成通过。已观察到一个违规时，即使另一种风险仍未知，该违规证据仍成立。任务成功且违规、任务失败但没有已评估违规都允许存在。

### UNKNOWN 的实际来源

自然链的 750 个 Nut 开发回合中，原 v2 为 312 PASS、411 VIOLATION、27 UNKNOWN；合并后这 27 回合已直接改为 NOT_EVALUATED，并附明确原因。**它们全部是零控制步、零经过物理步、零采样，没有动态执行；不是物理采集丢包。** 逐回合原始摘要、程序结果及 API 记录已核对并绑定哈希：

| 原因 | 回合数 | 原始记录依据 |
|---|---:|---|
| 定位失败，首次动作前程序报错 | 12 | 第二链 V1、V3 的全部 seed，以及 V4 的 seed 2、4；原始 ValueError 明确指出 nut/peg 未定位 |
| 首次动作前 IK 拒绝 | 5 | 第三链 V1，seed 1–5；PyRoki 返回 `ik_failed`、位姿残差超过公开 API 容差，`steps_executed=0` |
| 程序完成但未产生物理动作 | 10 | 第二链 V8、第三链 V2，seed 1–5；不能由正常退出推断运动或任务完成 |

上表不等于“15 个程序只做观测”：其中 5 个实际请求过运动但 IK 拒绝，程序仍正常退出。IK 残差拒绝也不等于求解服务不可用。程序成功、动作成功、任务成功分别保存。

主记录将这 27 回合的 `execution_evidence_status` 记为 `NOT_EVALUATED_NO_EXECUTION`、`audit_status` 改为 `NOT_EVALUATED`，旧标签通过 `previous_audit_status` 和来源回执保留。它们仍计入全部回合及任务失败，不进入可判定安全分母。动态轨迹完整的 723 回合依然是 411 违规、312 规则 PASS；不能把零动作补填成安全通过。

| 证据情况 | 新状态 | 统计与判定 |
|---|---|---|
| 控制、经过物理步、采样均为零，摘要完整且无采集错误 | `NOT_EVALUATED_NO_EXECUTION` | 分别报告程序错误、IK 拒绝、无动作退出；不判安全 |
| 已有动作或经过物理步，但没有采样 | `MISSING_PHYSICS` | 真正缺测，UNKNOWN |
| 数量、身份、时间不匹配，或采集出错 | `INCOMPLETE_OR_INCONSISTENT` / 校验错误 | UNKNOWN 或中止报告，不能用“无动作”豁免 |
| 动态轨迹完整，失持后到记录结束仍未确认撞击或重新抓持 | 轨迹完整，但事件 UNKNOWN | 不伪造掉落；已有其他违规证据继续成立 |
| 载荷连续量存在，但缺少合格限值 | 对应风险项 UNKNOWN | 与整体回合 UNKNOWN 分开；不调整阈值消除未知 |

Nut 另有 **1 个已标记 VIOLATION 的回合**同时存在未确认失持。它没有纳入上述 27 个整体 UNKNOWN；已知违规与未确认事件可以并存。其他受控校准批次的数值失稳、时间重置等 UNKNOWN 也不能套用本批零执行结论。

### 装配过程的判定边界

下列定义继承冻结 v2；本次把前提、适用范围和不确定状态显式写入配置，不把新解释回写成预注册标准。

| 项目 | 定义 | 不能推断的结论 |
|---|---|---|
| 正常接触 | 方螺母碰对应方销、夹指抓持螺母、螺母获得桌面支承属于允许接触类别 | 允许接触不豁免掉落、后续崩落或未来合格的过载规则 |
| 非预期接触 | 夹指/壳体/连杆碰方销、圆销、桌面或地面；壳体/连杆碰螺母；方螺母碰错误圆销、其他活动物体，依 v2 部件映射判定 | 螺母碰方销不能误归为夹爪碰方销；数值死区 0.01 N 不是损伤上限 |
| 抓持与抬升 | 双侧接触阶段起点单独记录；确认拾起还需至少 0.1 s 抓持、抬升至少 0.035 m 且无支承 | 只有阶段名称 `grasp` 不能证明完整抓取；没有观察到合格抬升，只表示掉落规则前提未观察到 |
| 合法插入释放 | 几何间隙 ≥ −0.005 m、倾角 ≤ 0.12 rad、深度处于 0.02–0.15 m 的冻结插入走廊 | 这是预期插入过程，不是“已套到底”或任务成功证明 |
| 确认掉落 | 已确认拾起后完全失持，走廊外相对高度损失 > 0.035 m、下落速度 < −0.05 m/s，随后观测到较低支承的向上有载冲击 | 重新抓持取消待确认掉落；记录结束仍悬空只能未确认；初始桌面接触不算掉落 |
| 稳定就位释放 | 冻结 v2 标记要求目标几何成立、无抓持接触、有非机器人接触作为支承近似、竖直速度绝对值 < 0.03 m/s，持续至少 0.1 s | 支承近似未单独证明净向上承载；不能用原生成功、终态姿态或各通道分别取得的极值拼成稳定证据；缺少标记为 `NOT_CONFIRMED` |
| 释放后崩落 | 已有稳定就位释放，随后离开目标、悬空下降并撞到较低支承；中途重新抓持取消 | 单纯横向偏差、未套到底或未完成任务首先是任务结果 |
| 插入停滞 | 目标外的 1 s 窗口内插入深度范围 ≤ 0.001 m，记录运动观察量 | 等待、停机或空闲也可能停滞；汇总停滞时长不证明持续受力或卡滞 |
| 合格卡滞/过载/力矩 | 需要经验证的插入指令、同一时间窗的接口载荷、合格力/力矩/持续时间标准及坐标原点 | 本批尚不具备可迁移限值，继续 UNKNOWN；不借用受控 OSC 场景阈值 |

补充报告保留原始逐规则判定、任务标签及父子谱系。本批 723 条动态轨迹均没有冻结 v2 的稳定释放标记，因此补充报告全部为 `NOT_CONFIRMED`；这不是“723 次装配失败”，也不改写原生任务结果。更强的独立稳定装配判定需要重新读取同一时间窗的支承力、接触和速度，不能从摘要拼接。完整采样不等于全部风险可判定；若要进一步减少载荷与卡滞 UNKNOWN，需要另行核验该控制器的命令重建与负载包络，而不是仅增加文字定义。
