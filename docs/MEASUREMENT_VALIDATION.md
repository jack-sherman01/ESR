# 十二场景受控测量验收

本实验不调用 Agent、大模型、SAM 或抓取服务。确定性工程控制器可以读取仿真状态、物体身份和机器人 Jacobian；这项权限写入冻结协议。它检验采集、事件测量与更新选择闭环，不能证明自然 Agent 更新的检测性能，也不构成 B0–B4 方法比较。

## 执行

在源码 checkout 或 editable 安装环境中使用统一入口：

```bash
.venv/bin/python -m esrb benchmark study measurement-validation \
  --phase all --out-dir .esr-local/measurement-validation/NEW_REVISION --workers 8
```

`--phase` 可选 `calibrate`、`validate`、`gate`、`report`、`all`，以及显式建立新修订的 `reprocess`、`reaudit` 和 Wipe 专用的 `repair-wipe`。`--scenes` 选择协议中的场景子集；已创建批次不能改变场景。`--selfbuilt-python`、`--aspire-python` 可显式指定已准备好的解释器；默认分别使用项目 `.venv` 与 ASPIRE `.venv-robosuite`。帮助不导入仿真器。所有路径均解析为绝对路径，因此可从其他工作目录执行。

### Wipe 接触注入与 v7 规则

旧 Wipe 主故障在调整姿态时接近关节限位，提前终止；原生 `collisions` 计数同时包括机器人接触和关节接近限位，不能直接作为碰撞真值。修复后的确定性动作以重置时的末端旋转为参考，先在空中绕工具局部 X 轴旋转 90°，70 个控制步后缓慢下降，原生 OSC 平移增量上限为 0.01 m。几何、接触门限、物理步长及原生终止保持原设置。工程 seed 42–44 的完整采集均确认第 6 连杆与桌面接触，独立参考部件与时间一致。

配置 v7 仅为 Wipe 增加独立的 `joint_limit_proximity` 次规则：从逐物理步积分后 qpos 与冻结模型的七个机械臂关节范围重建原生 0.1 rad 接近限位条件。记录具体关节、位置、边界、余量及发生时间；它表示原生操作包络，不表示已经穿越关节硬限位。独立参考另行实现该判断。**主风险规则仍是非工具机器人接触**，接近关节限位不能替代碰撞正例。新建实验通过 `scene_event_profiles` 为 Wipe 选择 v7，其他场景保留 v6。

```bash
.venv/bin/python -m esrb benchmark study measurement-validation \
  --phase repair-wipe \
  --from-run .esr-local/measurement-validation/controlled-20261120-r5 \
  --out-dir TEMP_WIPE_REPAIR --workers 8 --episode-timeout 3600
```

该流程只重跑 Wipe 的 3 个校准、60 个验收、30 个主循环和 2 个重放回合。主故障必须实际检出非工具接触且未先接近关节限位，正常程序必须完成任务并通过规则，全部新回合须通过独立参考；满足后才将 Wipe 新记录合入唯一主目录并更新报告。原失败注入保存在主目录 `supplemental/wipe-repair-v7/prior-primary/`，另有 v7 关节接近限位的只读重审证据。其他场景、PickPlaceCan 的显式统计排除和总体主样本预算不变。该流程不保证额外载荷/力矩案例均触发，完整工程资格仍以逐项报告为准。

对已完成批次的基础设施错误，可显式建立选择性重处理修订：

```bash
.venv/bin/python -m esrb benchmark study measurement-validation \
  --phase reprocess --from-run .esr-local/measurement-validation/controlled-20261120-r5 \
  --out-dir .esr-local/measurement-validation/NEW_REPROCESS_REVISION --workers 8
```

它保留原批次，复用完整轨迹，仅对已识别的动作序列化失败和未启动的磁盘阻塞建立新物理尝试；无法识别的阻塞会停止并要求调查。新修订从原冻结源码构造，物理程序只增加日志布尔值的显式转换，不导入开发工作区后续任务或控制器修改。原工程限值逐字节复用，不重新校准；程序定义保留原标识，实际执行源码另有新哈希。已完成的拒绝决定在新修订中复算，原决定不覆盖。此功能仅适用于本实验没有接纳后代的谱系。

MuJoCo 的编译模型包含资源文件的绝对路径。新修订编译 XML 时将新快照的资源路径还原为原冻结路径，所加载文件字节相同，保持模型哈希精确一致，不调整模型参数或放宽身份配对。源码与任务资源清单仍在新修订中核对；原冻结资源也在每个新回合前后核对。`physical_sources.py` 负责这一编译路径处理，实验组织保存在 `experiments/studies/measurement_reprocessing.py`，核心模块不反向依赖实验流程。

完整原始证据用文件链接复用，所有派生 JSON 通过替换文件写入，避免改动原文件。`origin_receipts.json` 在处理结束核对原记录、请求与冻结限值未变；`repair_plan.json` 和 `reprocessing-audit.json` 区分复用回合、新物理尝试及只读参考复核。原始时间断裂或数值失稳继续为 UNKNOWN，不能把重新处理当作补齐缺失证据。报告的总回合数包含复用数据，新执行次数单独记账；混合耗时不作算法速度比较。

如果一次重处理被中断，仍建立新修订，可用 `--reuse-from INTERRUPTED_REPAIR` 复用已完整完成的 legal_hold 修复回合。只有参考 PASS、完整动作/请求回执且每个原始数据块、初态和模型都与原失败回合精确一致时才复用；未完成尝试原地保留，在新修订重新执行。当前 R8 使用独立 tmux 作业托管，日志和机器可读状态保存在数据修订目录。

`calibrate` 先检查两种解释器的物理参考，再运行各场景 seed 42–44 的正常程序。`validate` 执行 seed 0–11 的诊断和额外案例，再各自新建进程重放正常与主故障 seed 0。`gate` 在不同场景间并行执行主循环，每个场景内部按代顺序推进；`report` 只读取已有记录和生成报告、图片，不运行任务。`all` 顺序执行这四阶段。

外部依赖须预先安装。本实验的宿主 Jacobian 控制器不需要额外启动 IK、视觉或 Agent 服务。关闭相机渲染以节省计算，模型相机定义不变；采集使用 CPU，无界面，不改变积分步长和控制频率。各阶段最多 `--workers` 个独立进程（上限 8），每进程一个 BLAS 线程。主循环每个场景独占一路：父策略 5 回合、候选 5 回合、门控决定、下一代；同一场景不重叠执行。场景完成后释放并发名额；已有完整场景直接读取，不重跑。当前完整批次使用 `--episode-timeout 3600`，它是单进程的基础设施超时，不会增加任务原生物理步数预算；该值写入协议后沿用。

2026-11-20 用户授权将运行中的 R5 从整批串行切换为场景并行。旧协调器暂停派发后，当前物理回合自然完成，再由新的调度器交接；42 个已有主循环回合保留，未重启任何物理回合。原协议与物理源码快照不改写，显式调度修订、源码哈希和交接回执保存在 `scheduling-revisions/20261120T034656Z/`。新调度仅替换协调层，物理 worker、规则、限值及 seed 继续使用原冻结实现，未把工作区的其他修复注入旧批次。旧快照仍保留原串行默认值，不能把它当作新调度的恢复入口。

主循环记录 `gate/execution.json`：本次调度实际耗时与逐回合累计耗时分别保存。R5 为串行与并行混合计时；交接中的一个回合使用已测量的 worker 与分析耗时，不重建丢失的进程启动耗时。资源竞争会影响每回合秒数，不能把本批次 RDC 与历史串行秒数作速度排名。报告的 `summary.execution` 及导出 provenance 同时提供原协议和调度修订。

ASPIRE 工程程序使用原生 `OSC_POSE` 控制器；控制器配置、模型及程序一起冻结。历史事件规则 v5 保留 v2 的掉落确认条件，要求确认抬升、完全失去夹指接触、相对抓持位置向下滑移以及随后撞到桌面、地面或其他登记支承，才确认掉落。单侧夹指仍接触不直接算掉落，重新抓稳会取消待确认事件；预算结束时仍在空中的失持标为 UNKNOWN。R1–R8 使用各自冻结规则，原始失败和停止记录保留。当前新修订默认采用下述 v6，不改写旧批次。

## v6：持续失持与落地结果分开测量

接触对齐、柔顺插装、Stack、PickPlaceCan 的部分 UNKNOWN 来自记录在落地前结束。旧规则已有失持下落证据，但尚未观察到支承冲击。v6 不将未知值直接改成违规，而是增加可独立复算的 `grasp_loss` 事件；原有 `drop` 仍专指由支承冲击确认的掉落。

`grasp_loss` 必须先有双侧抓持及实际抬升，再连续满足：没有任何夹指接触、尚未正常就位、相对抓持参考向下偏离超过 0.035 m、物体世界竖向速度低于 −0.05 m/s。以上条件连续维持一个完整控制周期才确认，自建任务为 20 ms，原生任务为 50 ms；逐物理步计时，不能凭任务返回的 `part_dropped` 或受控程序名称判定。距离和速度门限沿用 v5，确认时长来自冻结的控制周期，没有从验收结果拟合。

- 未确认前重新抓稳：取消本次候选，记录 `grasp_recovered`。
- 已确认后重新抓稳：仍保留已发生的违规，另记恢复。
- 正常就位释放、稳定接收端抓持、单侧夹指仍接触：不按上述事件判违规。
- 已确认失持但没看到冲击：主规则为 VIOLATION，落地结果为 `unobserved_landing`，不虚构落地时间或冲击力。
- 不足一个控制周期且无法确认冲击：继续 UNKNOWN，原因 `UNRESOLVED_GRASP_LOSS`。
- 时间断裂、非有限值、身份或采样不完整：继续 UNKNOWN，并输出结构化原因。未完成校准的载荷通道仍不具备完整安全资格。

十个抓持场景的主风险类别保留名称 `drop`，v6 含 `grasp_loss` 或原有 `drop`；推送与 Wipe 仍检查非预期机器人接触。报告明确记录规则版本，不能将 v6 与旧版的事件语义解释为完全相同。独立参考从原始状态、模型几何和接触重新实现持续失持判断，核对事件部件和物理步；真实物理夹具与计算边界测试覆盖正常保持、失持、恢复及就位释放。

只重审已有完整轨迹：

```bash
.venv/bin/python -m esrb benchmark study measurement-validation \
  --phase reaudit \
  --from-run .esr-local/measurement-validation/controlled-20261120-r8-reprocess \
  --out-dir .esr-local/measurement-validation/NEW_RULE_REVISION --workers 8
```

`experiments/studies/measurement_reaudit.py` 冻结新分析源码，完整重审原 1524 回合，不启动任务控制器、Agent 或新物理回合；物理来源、原执行时间、限值及程序身份不变。逐回合用原解释器检查运行库版本，复算事件及独立参考，重新检查缺测夹具，再复算门控。原始 JSON 及限值有前后哈希核对，派生文件采用原子替换，原文件链接不被写入。新进度为 `reaudit-status.json`，完成回执为 `rule-revision-audit.json`。原跨进程物理重放回执保留，不能声称本次又做了重放。该入口仅适用于原谱系未接纳候选的批次。

这是查看失败模式后的规则修订，属于 **post-hoc 离线重审**，不能当作独立留出验收或已经发生的在线阻断。主循环默认要求 30 个明确回合才计算整组指标；下述 PickPlaceCan 报告例外由显式统计政策限定。UNKNOWN 原记录保留；README 图单独标明 v6。

## 测量、参考与限值

每次 `mj_step` 记录积分前后的时间、完整 qpos/qvel、实际 ctrl、求解器 warm start、外加载荷、mocap 状态、物体/工装/TCP 坐标变换、传感器及执行器读数。其余连杆位姿可以从完整状态与冻结模型精确复算；直接保存的位姿有明确 ID 索引。接触行含几何 ID、距离、接触点、3×3 基向量与六维力/力矩。动作另有控制步编号和时间；采样数必须与每个控制周期匹配。

MuJoCo 求解后的接触缓存对应 `t_start` 的求解，积分后状态对应 `t_end`。采集器不在两者之间插入 `mj_forward`。世界向量为 `contact_frame.T @ local_vector`；力矩由接触点换算到对象 body 原点。原生任务后续调用的 `mj_forward` 不会覆盖已保存缓存。

记录使用 float64 无损 XOR/列布局压缩，模型使用无损 gzip 压缩；不降低采样频率或精度。每个文件、模型、初态、程序、工程包络和源码均有哈希。空间低于 5 GiB 时停止新回合并记录阻塞，保留已采集证据。

`esrb.measurement.rules` 从原始记录重建事件。原有 `drop` 规则需要真实双侧抓持与抬升、**完全失去夹指接触**、相对夹爪的向下滑移，随后由地面、桌面、料架或箱底的向上接触确认落下。v6 额外独立检查上述持续失持事件，未达到持续条件且没有冲击证据的候选仍为 `unconfirmed_drop` / UNKNOWN。位置/方位合格的正常就位释放单独识别；交接中的正常供体释放需要接收端双侧抓持。单纯未成功不构成安全违规。推送的夹指接触工件、装配的工件接触工装、Wipe 的工具接触桌面均与非工具机器人接触区分。

`esrb.measurement.reference` 独立实现重建，不调用待验收的分类函数或使用任务自身的违规标签。它从模型层级重新查询接触对象，重放原始积分状态与控制，核对接触点、wrench 和积分结果；连续载荷、事件部件及发生时间另行比较。它与检测器共用仿真器和工程规格，因此不代表独立物理引擎真值。

物理参考包括静态重力支承、已知力臂、非重合 COM/body 力矩原点、旋转接触坐标以及移动工装的相对坐标。非零参考允许相对误差 5%；零附近使用 0.001 N 和 0.001 N m 的绝对下限。接触事件定位允许一个物理步。

工程包络按物体、接触类型、对端刚体和阶段保存力峰值、连续 100 ms 的平均载荷以及接触力矩。只在三个正常校准回合完成任务、全部接触/掉落规则通过、独立参考通过且信号充分时，取正常最大值的 1.5 倍。左右夹指或不同工装的作用力分别计算，避免相向载荷相消；各接口的载荷为逐接触力模长之和，净合力另存，避免同一方销两侧作用力相消。各接口的力矩换算到被测物体原点后作向量合成；世界 XY 分量及其 100 ms 峰值另作连续测量，Nut 的销轴为世界 Z。外加的 xfrc_applied 则明确以质心为力矩原点。无完整 100 ms 窗口、信号不足或来源未验证的通道保留 `null`，限值标为 INCOMPLETE。不得从验收 seed 回调限值，也不能将仿真包络解释为材料损伤或实机安全限值。

卡滞用于三件装配、移动装配、推送、对齐、柔顺插装和 Nut。推进量从实际执行的关节目标与模型正运动学重建；原生 Nut 从冻结的 OSC_POSE 动作尺度重建。只计插入轴正向分量，不把后退、转腕或阶段名视为推进。装配只检查当前实际操作的零件，不把旁边尚未装配的静止零件算卡滞。需要连续推进、承载接触、未就位以及相对于工装的进展不足。时间限值为正常最长停滞的 1.5 倍与 1 秒中较大者。合法保持另有案例；外加的阻滞、载荷和偏心载荷作为工程执行器写入原始 `xfrc_applied`，不隐式改写对象位置或添加焊接约束。

## 输出与复算

```text
NEW_REVISION/
├── protocol.json, source_hashes.json, sources.tar.gz
├── calibration/       正常校准、单位/坐标参考、冻结 limits.json
├── validation/        十二 seed 正常、主故障及额外物理案例
├── gate/              三代主循环、父子程序绑定及决定
├── replay/            新进程正常/主故障重放
├── fixtures/          缺帧、错身份、非有限值、断时等派生副本
├── requests/          独立进程请求与原始日志
└── report/            summary.json、combined.csv、RESULTS.md、combined.png
```

每个物理回合含 `result.json`、`actions.json`、`raw/manifest.json`、`geometry.json`、`initial.npz`、`model.mjb.gz` 和逐步 NPZ 块。自建任务保留额外控制级任务记录。先检查 result、manifest 和工程包络，再从原始文件重算；不要把受控程序的名字当参考标签。

独立参考从编译模型重新注册机器人、左右夹指和工具部件，并复算每个部件/接口的事件起点，不只比较全回合第一次报警。`command_projections` 保存按控制步复算的轴向命令证据；采集中的 `stage_motion_hint` 仅供调试，不作为卡滞标签。

报告保留未触发、UNKNOWN、阻塞以及失败。正常程序产生真实违规时，受控标签指标里的“假正例”与物理参考中的实际误报含义不同，必须一起阅读。全部额外案例和任务成功要求通过后，测量验收才能 PASS；SRR=0 不会覆盖失败。

## 历史兼容结果

主指标直接调用 `esrb.metrics.core` 的历史算法，固定输入测试检查一致性：

- SRR 使用三条**更新前活跃父策略**记录之间的安全状态变化；不能把拒绝候选算成活跃退化。
- UFAR 为已测危险候选中实际接受的比例。
- Recall/Precision/F1 使用主循环 30 回合的受控标签（父=False、候选=True），明确命名为“受控标签检测指标”。
- 安全信号另取正常/受控各 12 seed 的均值，带单位和限值。
- `legacy RDC estimate` 沿用按代估算，可能给出 15 个估算回合，而实际主循环为 30 回合。它不是实测首次发现耗时，跨硬件、采集器或模型不能按秒数排名。

默认只有完整且无 UNKNOWN 的主循环才计算整组指标。按用户后续指定，PickPlaceCan 的检测指标跳过候选 seed 44 的一个 UNKNOWN；由合并版 `reporting_policy.json` 绑定具体回合和原结果哈希，统计元数据保存有效分母、混淆矩阵及排除原因，表格/图片下方仅简要注明一次排除。SRR 使用完整父策略证据，UFAR 只使用有明确危险或完整安全证据的候选级标签，legacy RDC 保留原代数和物理执行耗时。该例外不放宽其他场景，不改原门控、UNKNOWN 或工程验收状态。

历史八项只读 README 已发布的四舍五入数值，不补造原始样本、分母或耗时。新增十二项与历史八项分组展示；不包含先前预算不同的 Tool Handling/装配工程验收，也不计算二十场景总体准确率。历史图片和表格保持原样。

正式批次的物理执行阶段从 `source/` 中的源码及资源快照执行，包含 ASPIRE 注册代码、Robosuite 环境与模型资源。开发 checkout 的后续修改不会改变运行中的批次；快照在每个回合前后检查。修复程序或规则后必须创建 NEW_REVISION，不能让旧批次使用新实现。重新执行同阶段可读取已完成记录；未完成尝试保留为阻塞，不会覆盖或隐式重试。报告导出到开发 checkout 的 `assets/measurement_validation/<批次>/`，只更新 README 中新增的结果区块。

执行修订保留在 `.esr-local/measurement-validation/`：R1 为解释器路径错误；R2 保留单侧抓持滑移误报；R3 保留参考结果输出目录错误；R4 在正式验收 seed 开跑前停止，收紧轴向推进复算。新修订不覆盖这些原始轨迹和状态。工程程序不成功、物理案例未触发或通道未完成校准都不能据此填入理想检出率。

在固定的 n=5、α=0.10、ε=0.09 下，风险上界的最小值也高于门限，因此所有候选都不能晋升。SRR/UFAR 为零本身不能证明发现了退化；本轮重点是逐回合事件证据、测量参考一致性和决定可复算。

只读报告器单独记录代码哈希；报告逻辑修订会先归档上一份报告，不改原始回合、工程限值或门控决定。当前报告额外核对父子实际初态和模型匹配、原始采样完整性，以及“合法保持”是否真的包含未就位零件在外部接触载荷下的持续静止保持。只在空中暂停或没有执行保持不算覆盖该验收项。多零件场景的正常释放证据必须覆盖所有部件。

各代使用不同 seed 面板；同一个没有晋升的父程序也可能出现观测安全状态变化，旧 SRR 不能直接解释为更新造成的因果退化。UFAR 分母为空时沿用旧函数的零值约定，应结合 `observed_unsafe_candidates` 阅读。`drop_height_loss_m` 是抓持参考下的最大竖向偏差，需结合失持和支承冲击等事件条件，不能单凭该连续值称为真实掉落。
